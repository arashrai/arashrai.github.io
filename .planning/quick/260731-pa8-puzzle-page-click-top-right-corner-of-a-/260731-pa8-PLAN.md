**A. Create the hit element (puzzle-ui.js, inside `renderGrid`, at the color-tag block around line 467-470).**

Insert the hit target BEFORE the existing `tagDotEl` so it is the immediately-preceding sibling of `.color-tag` (required by the CSS `+` selector from Task 1). Name it `tagHitEl` per the `El` convention:
   - `const tagHitEl = document.createElement("span");`
   - `tagHitEl.className = "color-tag-hit";`

   - `frontEl.appendChild(tagHitEl);` then the existing `tagDotEl` creation/append follows unchanged.

Leave `tagDotEl.className = "color-tag"` exactly as-is: the restore loop at puzzle-ui.js:421-428 does `querySelector(".color-tag")` and must keep matching exactly one element per card.

**B. Add handlers on `tagHitEl`, placed immediately after the existing cardEl `keydown` handler (i.e. before the `contextmenu` handler at line 509) so the color-marker handlers read as one group.**

1. Click handler:
   - `event.stopPropagation();` FIRST (design decision 2) so `handleCardClick` never runs and the guess dialog never opens.
   - Guard: `if (cardEl.classList.contains("flipped")) return;` (design decision 5) — a flipped card's front face and its dot are not visible, so cycling there would be an invisible state change.
   - `const tagColor = NARSH_PUZZLE.cycleColorTag(i);` then `tagDotEl.style.backgroundColor = tagColor;` — identical to the existing contextmenu handler, including the `"transparent"` (index 0) clear step.

2. Touchstart handler (`{ passive: true }`), doing ONLY `event.stopPropagation();`:
   - The card's own `touchstart` listener (line 518) starts a 300ms long-press timer that also cycles. Without this, a corner tap held >300ms would cycle once from the long-press AND once from the synthesized click = double cycle. Stopping propagation at the hit target prevents the card timer from ever starting, so a corner touch always cycles exactly once via the click handler. `stopPropagation` is legal inside a passive listener (only `preventDefault` is not).

Do NOT add a `contextmenu` handler to `tagHitEl`: right-clicking the corner bubbles to the card's existing handler and cycles once, which is the desired behavior.

**C. Accessibility note (design decision 4) — record this as a code comment above the `tagHitEl` creation, and repeat it in the SUMMARY.**

The hit target is deliberately NOT focusable (no `tabindex`, `aria-hidden="true"`, a `<span>` not a `<button>`). Reasons: the grid renders one target per character card, so making them focusable would roughly double the tab stops on the page for a secondary note-taking affordance; and the card's own `role="button"` / `tabindex="0"` / Enter-Space path to the guess dialog must stay unchanged. Keyboard-only users retain the pre-existing path to color cycling: focus the card and press the context-menu key (or Shift+F10), which dispatches `contextmenu` on the focused card and hits the untouched handler at line 510. Net a11y change: zero regressions, no new tab stops, no new labels needed.

Do NOT modify the cardEl `click`, `keydown`, `contextmenu`, `touchstart`, `touchmove`, or `touchend` handlers (design decision 3 — this adds a way in, it removes nothing).

**D. Refresh the three stale comments (design decision 6).** Repo-wide grep confirms these are the ONLY places mentioning right-click/long-press; there is no user-facing copy to change, so do not add on-page instructions.
   - `puzzle.js:9` -> note the 7 colors cycle via a corner click/tap, with right-click (desktop) and long-press (mobile) as alternates.
   - `puzzle-ui.js:509` -> "Desktop: right-click also cycles color tag (alternate to corner click)".
   - `puzzle-ui.js:516` -> "Mobile: long-press (300ms) also cycles color tag (alternate to corner tap)".
