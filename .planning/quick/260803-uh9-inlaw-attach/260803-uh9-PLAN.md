## Correction 1 — there is NO cross-tree marriage. The connector is a parent edge.

R2 as briefed says "look for a marriage between somebody in R's subtree and somebody in another
tree T". **That marriage does not exist and cannot exist.** `layoutSide` union-finds every
same-side marriage into a single couple unit, so a married pair always lives in exactly one tree.
Scanning all 42 MARRIAGES against the computed unit trees returns **zero** cross-tree marriages
on either side.

The real connector is the **non-hierarchy parent edge** — a person in root R's subtree is the
CSV-declared parent of a person who, because of their own marriage, got laid out inside tree T.
There are exactly 3 such edges on arash's side and 1 on natalie's:

| parent (tree R, depth) | child (tree T, depth) | d = d_child − 1 − d_parent |
|---|---|---|
| Balbir Rai (VIRT sibgroup, 0) → | Amritpal Rai (Jatinder tree, 1) | 0 |
| Amrit's mom (Amrit tree, 0) → | Amrit Kaur (VIRT sibgroup, 2) | **1** |
| Amrit's dad (Amrit tree, 0) → | Amrit Kaur (VIRT sibgroup, 2) | **1** |
| *(natalie)* Mary Fleury (Mary tree, 0) → | William Fleury (Sidney tree, 1) | 0 |

The briefed arithmetic is still exactly right, just re-expressed: `dSpouse` is the T-side
person's unit depth, `dMarrier` is the R-side child's would-be depth in R (= parent depth + 1),
so `d = dSpouse − dMarrier = d_child − 1 − d_parent`. For Amrit: `2 − 1 − 0 = 1`. ✓

## Correction 2 — fallback (b) must be guarded, and does not fire on today's data.

Both `d = 0` rows above involve the **target lineage** as T. Blindly applying fallback (b)
("place R immediately to the right of T") to the natalie row would move `Mary Fleury` to the
right of `Sidney Morehouse`, putting Mary's tree on the inner edge and breaking the
"Natalie edge-pulled right / adjacent to Arash" invariant the handoff protects.

So fallback (b) is implemented **with a guard**: a reorder is rejected if it changes which
entry sits at the inner-edge terminal position (LAST for natalie, FIRST for arash). On current
data both `d = 0` candidates are rejected and root ordering is byte-identical to today. That is
the correct outcome — do not "fix" it.
